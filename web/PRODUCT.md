## Platform

web

## Users

- End users author and inspect private local environment declarations and complete native configuration.
- Account users review their synthetic profile associations, usage, subscriptions and support.
- Operators inspect synthetic customers, scoped authority, service intents, audit and health separately from the local client.

These roles and boundaries are confirmed in the user instructions and the repository contracts. This record is scoped to the browser package; it is not a replacement product specification.

## Product Purpose

Make local configuration work practical and understandable without uploading the user's configuration. Keep the client, account and operator surfaces coherent while distinguishing authored configuration, simulated service behavior and actual qualified native/backend capability.

The canonical repository contracts remain `docs/product-guide.md`, `docs/implementation-plan.md`, `docs/managed-key-service.md`, `SECURITY.md` and the source-owner handoff. This browser record cannot narrow their full v1 obligations or qualify a deployed service.

## Operating Context

Existing dependency-free JavaScript/HTML/CSS, Node 22+ development server. Two loopback listeners: local client on 5181, synthetic account/operator on 5180. Matt confirmed phone access through his existing authenticated Termux SSH forwarding. Each browser/origin owns its own saved state.

## Capabilities and Constraints

- Edit/import/export environment declarations with masked values, provider/key references, independent timezone windows, inheritance/conflicts and whole-candidate mock feedback.
- Author all supported fields of the pinned native schema through typed controls or local JSON. Preserve unknown fields as invalid drafts, explicit values and untouched source. Never silently replace a separate draft.
- Account/operator interactions are synthetic. UI persona selection is not authentication. No real key release, issuer, billing, fleet or maintenance endpoint is connected.
- No configuration upload, remote fetch proxy, new public tunnel, paid service, production deployment or operational credential access is authorized by this package.
- Preserve existing drafts, the single preview process budget and current source-owner integration authority. BAU has priority on actual resource contention.
- Impeccable Live Mode is deferred. Discovery, critique, planning and appropriate local UI changes are authorized; no hook/server activation is implied.

## Product Principles

- Keep private configuration on the user's client.
- Make the useful task visible before decorative explanation.
- Preserve source, drafts and atomic denial behavior.
- State simulation and authority limits honestly.
- Keep desktop and narrow-screen actions, language and feedback consistent.

## Accessibility & Inclusion

Use native keyboard-operable controls, visible focus, non-color status text and labelled inputs. Verify relevant desktop and 320/390px browser layouts, sufficient text contrast and usable touch targets. Existing checks are not assistive-device certification.
