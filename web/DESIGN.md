# Design System: CircularQuay browser surfaces

## Overview

This is a scan of the current implementation, not a new binding visual identity. The user fixes only icon 13 and explicitly permits Impeccable to recommend and implement broader visual changes. No invented visual metaphor or unapproved approval claim is recorded.

The current interface uses functional navigation, local typed editors and data tables. Visual ambition should support completing configuration/service tasks and must not turn simulation into a live-service claim. Canonical product/security contracts remain authoritative.

## Colors

The frontmatter records current `style.css` tokens. Token changes require a documented design and accessibility review. Light/dark themes are user-selectable; the selected logo must remain visible in both. Do not invent unrelated marks or silently substitute a generic icon.

## Typography

Current implementation uses the platform UI sans stack, compact operational labels and monospace only for data/code. Ordinary form values are 14px on desktop and 16px in narrow layouts; headings distinguish the task from supporting scope/status. This is an incumbent record, not a requirement to retain the current font.

## Layout

Local configuration uses a desktop section rail and a native section selector on narrow screens. Destinations are grouped into Sources, Workloads, Access and Advanced configuration; unsupported roots remain visible and escaped. Provider and optional-field menus use native option groups. Primary actions stay visible; secondary actions use a keyboard-operable disclosure. The environment workbench pairs a masked table with a guided inspector. Account/operator surfaces retain their separate navigation and synthetic capability context.

Current control minimums are 40px desktop and 44px narrow. Spacing follows 8/12/16/24px groupings. Tables may scroll within focusable regions; the whole page must not overflow at 320/390px.

## Elevation & Depth

Most surfaces use borders/tonal separation. The secondary-action disclosure and dialogs use restrained offset blur. Avoid decorative depth competing with fields and data.

## Shapes

The current stylesheet uses small rounded controls and modest panel radii. These are observed implementation choices, open to critique. Keep the selected logo geometry authoritative, including its open C, bow, shaft and two teeth.

## Components

- **Brand:** exact icon-13 crop and provenance remain preserved. Transparent logo-light.svg (navy) and logo-dark.svg (off-white) share reconstructed native geometry and are used by every wordmark, including the landing page. They are derived assets, not original vector source. Theme selection follows the application theme and system preference.
- **Configuration:** one-step removal undo restores the complete proposal and invalid numeric inputs until the next edit, save or document replacement. Original/proposal separation, explicit optional fields, schema/reference feedback, invalid-draft preservation and actionable failure states.
- **Controls:** concise verbs, native semantics, stable disabled/error states, visible focus, Escape for the secondary-action disclosure.
- **Service previews:** current model labels override stale persisted presentation metadata without replacing saved records.
- **Language and theme:** native labelled selects in an expanded landing disclosure and compact task disclosure, with resolved outcome/source captions. Arabic is explicitly a preview; English product content retains its actual language metadata. Theme/language changes preserve forms. Controls load independently before app startup, with a pre-CSS theme/language bootstrap. Logical spacing and isolated code keep RTL and English machine text readable.
